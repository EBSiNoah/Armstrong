# 제출 원문 정합성·이동·데이터 보존 점검

## 목적과 판정 범위

이 문서는 현재 제공 저장소의 실행 진입점, 버전 안내, 학생 구현 계약, 재현 기록, 선택형 호스트 설정 및 저장 경계를 문서·코드에서 대조한 **정적 점검 기록**입니다. 학생 성취 평가나 제품 승인 문서가 아닙니다.

이번 점검에서 Git 저장소의 현재 HEAD·원격 URL·브랜치·40자리 해시를 확인하지 않았고, 파일을 실행하지 않았습니다. 따라서 이 점검은 코드 원문 검토 증거일 뿐, 앱 기동·브라우저 화면·테스트 통과·실제 AI/SDP/XDR/OSV 연결의 증거가 아닙니다. 별도 실행 증거가 없는 값은 미확인으로 기록해야 합니다.

## 2. 새 환경으로 이동·재현하는 안전한 절차

### 2.1 커밋을 고정해 새 작업 폴더 만들기

원본 작업 폴더를 보존합니다. 원본에서 커밋되지 않은 변경은 복제한 커밋에 포함되지 않으므로, 필요한 변경이 있으면 먼저 적절히 커밋하고 40자리 해시를 기록합니다. 저장소 URL에 비밀 인증 정보를 포함하지 않습니다.

```powershell
$Repo = "<비밀값이 없는 저장소 URL>"
$Branch = "<기록한 브랜치>"
$Commit = "<40자리 전체 커밋 해시>"
$Repro = "<원본 바깥의 새 빈 폴더>"

git clone --branch $Branch --single-branch $Repo $Repro
git -C $Repro checkout --detach $Commit
git -C $Repro rev-parse HEAD
git -C $Repro status --short
```

`rev-parse HEAD`가 기록한 전체 해시와 일치해야 합니다. 일치하지 않거나 비교 근거가 없으면 실행을 중단하고 `동일 커밋 검증 불가`로 적습니다. 원본의 `.env`, NativeHost/SDP 설정, 인증서, 개인키, 토큰, 외부 Vault·registry 파일을 복제본으로 복사하지 않습니다.

### 2.2 런타임과 기본 실행

1. 새 폴더 안에서 `on-client`로 이동합니다. 해당 폴더에 `package.json`, `tools`, `src`가 함께 있어야 합니다.
2. 실행 환경과 시각을 기록합니다.

```powershell
node --version
npm --version
$PSVersionTable.PSVersion
```

3. 매니페스트·해당 커밋의 안내를 먼저 확인합니다. 이 제공본의 매니페스트는 Node `24.19.0`을 선언하며, 시작 스크립트는 22~24 주 버전을 허용합니다. 정확한 버전과 실제 기기에서의 지원은 별도로 기록합니다.
4. 현재 제공 매니페스트에는 외부 npm dependency가 없으므로, 이 구성에서 `npm install`은 기본 절차가 아닙니다. 다른 커밋에 의존성이 있다면 그 커밋의 안내에 따라 설치하고 명령·결과를 남깁니다.
5. Windows PowerShell의 학생 기본 실행 진입점은 다음과 같습니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

6. 기본 URL은 `http://127.0.0.1:5189/`입니다. 포트를 바꿨다면 시작 도구에 지정한 포트와 브라우저 주소를 함께 기록합니다. 종료는 같은 PowerShell 창의 `Ctrl+C`, 재실행은 같은 복제본·같은 커밋에서 실행 절차를 다시 수행하는 것입니다.
7. `npm start`는 매니페스트의 직접 서버 진입점이고, `npm run demo`는 예제 데이터입니다. `npm run check`는 학생 모듈의 문법만 검사합니다. 이 명령들의 결과를 브라우저 동작·실제 시스템 연결·공식 과제 통과로 확대하지 않습니다.

macOS/Linux, 특정 브라우저, Node 22~24 전체에 대한 호환성을 확인한 것으로 간주하지 않습니다. Windows PowerShell 실행 도구 외 환경은 별도 시험 근거가 있을 때만 지원 범위에 포함합니다.

### 2.3 설정 예시와 이동 경계

기본 연결 없음 실행에는 별도 개인 설정 파일이 필요하지 않습니다. 담당자가 NativeHost를 발급한 Windows 환경에서만 아래와 같은 **구조 예시**를 사용합니다. 경로는 가짜 예시이며, 임의로 파일·폴더를 만들거나 값을 채워 실제 연결을 시도하지 마세요.

```json
{
  "enabled": true,
  "registryRoot": "C:\\AlekovPrivate\\native\\registry",
  "vaultRoot": "C:\\AlekovPrivate\\native\\vault",
  "projectRoot": "C:\\Students\\MyProject",
  "gatewayOrigin": "https://ai-classroom-gateway-production.up.railway.app",
  "portalOrigin": "https://aleph-omega.vercel.app"
}
```

이 예시의 구조는 `src/connection/native-context.mjs`와 `tools/prepare-native-host.ps1`에서 확인한 선택형 설정 경계입니다. 실제 설정은 담당자가 제공해야 하며 프로젝트·registry·Vault 경로와 Windows ACL·사용자 계정·디렉터리 identity를 해당 환경에서 확인합니다. 아래처럼 실행기에 전달합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -NativeHostConfig "<담당자가 제공한 Windows 절대 설정 파일 경로>"
```

NativeHost는 Windows 전용이며 설정에 Windows 절대 경로가 있습니다. 다른 PC로 이동할 때 설정·인증 파일을 복사하지 말고 담당자에게 대상 환경용 설정과 계정 연결을 새로 안내받습니다. SDP 설정은 별도 계약이며 NativeHost 설정과 혼용하지 않습니다. SDP JSON 스키마가 안내되지 않았다면 추측해 만들지 말고 `docs/SDP_HOST_CONNECTION.md`의 담당자 절차를 따릅니다.

선택형 조치 설정은 이미 있는 SQLite 파일의 경로와 닫힌 정책을 필요로 하며, 시작 설정 검증은 DB 파일을 새로 만들거나 이전하지 않습니다(`src/actions/action-startup-config.mjs`). 조치 원천 실행은 기본 실행이나 이 예시로 보장되지 않습니다. 학생이 임의 DB·정책을 만들어 활성화하지 않습니다.

절대경로가 들어가는 별도 설정은 이동 가능한 소스 코드의 일부가 아닙니다. 소스 복제 성공과 개인 설정 복원·실제 연결 성공은 각각 따로 기록합니다.

- 새 폴더에서 읽은 HEAD 해시와 원본 해시 일치 여부
- `package.json` 버전, Node·npm·PowerShell 버전, 운영체제, 브라우저 종류·버전, 실행 날짜·시각·시간대
- 새 환경에서 사용한 설치/준비 절차, 실제 실행 명령·포트, 브라우저 확인, 종료와 같은 커밋에서의 재실행 결과
- 단계별 관찰한 화면·결과·근거 ID와 확인 시각, 오류 코드·미확인 원인
- 자료 종류: `demo` 모의 자료 / 연결 없음 / 실제 시스템 응답 / OSV 공개 조회. 종류를 서로 대체하지 않음
- 수정 후 새 커밋이 생겼으면 새 행·새 해시를 만들고 그 커밋에서 재검증한 범위만 기록

재현 양식의 `미확인`을 확인됨으로 바꾸려면 실제 증거를 추가해야 합니다. 다른 커밋의 성공 결과를 하나의 최종 버전 결과로 합치지 않습니다. 22단계 재현·완료까지 보고하는 제출물은 현재 13~21 표만으로 충분하지 않으므로 22단계 결과도 별도로 기록합니다.

### 증거 유형을 섞지 않는 규칙

| 유형 | 무엇을 뜻하는가 | 허용되는 표현 |
|---|---|---|
| 원문 검토 | 코드·매니페스트·문서를 읽고 계약이나 잠재적 차이를 찾음 | “정적으로 확인”, “문서에 기재”, “미해결 계약 차이” |
| 모의 자료 | `npm run demo` 또는 합성 fixture가 제공한 예제 응답 | “예제 화면 확인”, “모의 자료 경로” — 실제 서비스 연결은 아님 |
| 학생 진술 | 학생이 실행했다고 보고한 내용. 근거가 첨부되었는지는 별도 | “학생 기록에 따르면” — 독립 실행 확인과 동일하지 않음 |
| 실제 실행 검증 | 특정 40자리 커밋·환경에서 실행했고, 시각·절차·화면/로그 근거를 남김 | 검증한 범위만 “해당 커밋에서 실행 확인” |
| 공식 판정 | ALEPH가 제출 커밋에 대해 반환한 판정 기록 | 화면의 공식 결과·접수 커밋 범위를 그대로 인용 |

AI가 저장소 원문을 검토하거나 문서를 작성한 것은 **AI 원문 검토**입니다. 그것만으로 학생 PC의 실행 성공, 브라우저 확인, 외부 서비스 연결, 단계 통과를 증명하지 않습니다. 기존 문서에 기재된 과거 시험은 해당 문서의 진술·기록으로 인용할 수 있지만, 현재 커밋의 재현 증거로 자동 승계하지 않습니다.

## 4. 데이터 보존·백업·복원 계획과 제한

### 4.1 보존할 데이터 유형과 확인된 제한

| 데이터 | 확인된 저장/생명주기 | 보존·백업 원칙 | 제한·미해결 |
|---|---|---|---|
| 학생 소스·문서·Git 이력 | Git에 커밋된 내용. 미커밋·미추적 파일은 커밋 복제본에 포함되지 않음 | 원본 작업 폴더를 삭제·덮어쓰지 않습니다. 새 폴더 재현 전 `git status --short` 확인, 필요한 변경 커밋 또는 별도 안전한 백업 | 원본 리포지토리 백업은 자동 제공되지 않습니다. 원격 Git에 개인 설정·비밀을 올리지 않습니다. |
| NativeHost 설정 파일 | 담당자 설정 경로, Windows 절대경로와 ACL·파일 identity 검사 | 저장소 밖의 담당자 승인 위치에 보관하고 새 환경에서 새 설정을 받습니다. 설정 내용을 제출 기록·Git에 넣지 않습니다. | 다른 PC/사용자 환경으로 단순 복사하는 이식 절차는 문서·코드에서 확인되지 않음. |
| Native registry | 설정한 별도 registry 경로에 프로젝트 대응·운영 상태 파일을 보관하는 구조 | 환경 소유자가 보존/백업 정책을 정하고, 앱을 중지한 뒤 승인된 백업 절차만 사용합니다. 원본을 덮지 않고 백업 사본의 무결성을 별도로 확인합니다. | 프로젝트 경로·디렉터리 identity와 사용자 환경에 결속됩니다. 용량 상한이 코드에 있으며, 복원·이전·삭제를 위한 학생용 UI는 확인되지 않았습니다. |
| 앱 AI 자격 Vault | NativeHost의 별도 Vault와 Windows `CurrentUser` DPAPI 보호를 사용하는 코드 경계 | 열쇠·자격 파일을 Git·증거에 넣거나 임의로 복사하지 않습니다. 환경 이동 때 담당자가 공식 재연결/재발급 절차를 제공해야 합니다. | DPAPI 및 사용자·Vault identity 때문에 다른 환경으로의 단순 파일 복원은 보장되지 않습니다. 이식·복구 성공은 확인하지 않았습니다. |
| 조치 기록 SQLite | 선택형 조치 설정이 명시적으로 가리키는 기존 SQLite 파일. 액션 intent/audit는 불변 트리거를 두는 코드 | 사용 전/후 DB 소유자와 보존 정책을 확인합니다. 앱이 DB를 사용 중인 상태에서 파일 하나만 복사하지 않습니다. 담당자가 앱을 중지하고 일관된 SQLite 백업 절차를 수행한 뒤, 복구는 원본을 보존한 별도 사본에서 검증합니다. | 학생용 백업/복원 명령·보존기간·삭제 절차를 확인하지 못했습니다. 불변 기록은 일반 사용자 삭제로 정리할 수 없도록 되어 있으므로 운영자가 보존·개인정보 정책을 정해야 합니다. |

| 취약점 조회 결과·demo 자료 | 스캔 함수는 결과를 반환하고 demo 데이터는 코드에서 생성 | 기록해야 하는 결과는 근거·시각과 함께 학생 문서에 수동으로 남기며 민감정보를 가립니다. | 일반 결과 보관·자동 백업을 수행하는 DB를 확인하지 못했습니다. demo는 재현 가능한 예제 자료이지 운영 데이터가 아닙니다. |

### 4.2 학생이 따를 최소 절차

1. **원본 보존:** 원본 작업 폴더를 유지합니다. 재현 폴더는 별도 빈 위치에 만들고 원본을 덮어쓰지 않습니다.
2. **커밋 보존:** 원본에서 URL·브랜치·해시와 `git status --short`를 확인합니다. 필요한 변경을 커밋하고 전체 해시를 기록합니다. 커밋되지 않은 파일은 별도 보존이 필요합니다.
3. **설정 분리:** `.env`, NativeHost/SDP 파일, 인증서·개인키·토큰, registry, Vault를 Git·새 폴더·제출물로 복사하지 않습니다. 환경별 설정은 담당자에게 발급받습니다.
4. **저장 데이터 확인:** 선택형 SQLite·registry·Vault를 사용하는 경우 데이터 소유자·경로·권한·보존 담당자를 확인합니다. 담당자 승인 없이 이동·삭제·초기화·덮어쓰기를 하지 않습니다.
5. **일관된 백업:** SQLite를 쓰는 환경에서는 운영자가 앱 중지 여부와 SQLite 일관성 확보 방법을 정한 뒤 백업합니다. 단순 파일 복사를 일관성 있는 백업으로 가정하지 않습니다. 다른 외부 저장 데이터는 담당자의 해당 저장소별 백업 절차를 따릅니다.
6. **복원 검증:** 백업본을 원본 위치에 바로 덮어쓰지 않습니다. 격리된 사본에서 파일 무결성, 소유권·ACL, 현재 계정·프로젝트 바인딩과 앱 접근 가능성을 담당자가 확인합니다. 복원 시험을 하지 않았다면 “복원 가능”이 아니라 “복원 미검증”으로 기록합니다.
7. **보존 종료:** 삭제·보존 기간은 코드에서 추측하지 않습니다. 학생 데이터, 감사 기록, 자격의 기간과 파기 방식은 데이터 소유자/운영자가 정해야 하며, 현재 문서 검토만으로 확정할 수 없습니다.

## 5. 지원 범위·버전·미해결 사항

### 현재 코드·문서에서 읽히는 범위

- 기본 앱은 로컬 loopback HTTP 서버이며 기본 포트는 `5189`; Windows PowerShell 실행 도구가 제공됩니다.
- 매니페스트는 Node `24.19.0`을 선언합니다. 실행기는 Node 주 버전 `22`~`24`를 허용하지만, 허용만으로 각 버전의 실제 호환성을 입증하지 않습니다.
- npm 외부 dependency가 선언되지 않은 기본 제공 구성입니다. 현재 `check`는 학생 확장 파일의 구문검사입니다.
- demo는 합성/예제 데이터입니다. 기본 실행은 실제 SDP/XDR 또는 AI 연결로 간주되지 않습니다.
- 선택형 NativeHost/SDP/조치 설정은 담당자 환경과 권한을 요구하며, 기본 실행의 지원 범위와 분리됩니다.
- 특정 OS(Windows 외), 브라우저·버전 전체 호환성, 운영 계정·실제 외부 서비스에 대한 이번 실행 증거는 없습니다.

### 제출 전 확인·수정이 필요한 항목

1. 최종 제품 안내서 버전 표제를 실제 기준 커밋과 맞출 것.
2. `AI_SETUP_GUIDE.md`의 `test` 스크립트 언급과 과거 버전 시험 결과를 현재 `package.json`·커밋과 분리하거나 갱신할 것.
3. 학생 UI의 `createStudentView({ api, onChange })` 호출과 `createStudentView()` 함수 서명 차이를 제공 코드 원문 담당자와 확인할 것. 확인 전 연동 성공 주장을 보류할 것.
4. `.env` 개발 안내와 학생용 비밀값 금지 절차를 명확히 분리할 것.
5. 제출이 22단계까지 포함한다면 재현 양식에 22단계 결과·근거·미확인 원인을 추가할 것.
6. NativeHost/SDP/SQLite 등 외부 저장 데이터에 대해 운영자가 보존기간, 백업 책임자, 복원·접근 통제·파기 절차를 확정할 것.
7. 선택 설정을 옮길 때 원본 사용자 데이터·자격을 복사하지 않는 재프로비저닝 절차를 담당자가 문서화할 것.
8. 최종 제출 소스에서 실제 실행할 때마다 커밋 해시와 환경·절차·관찰 결과를 재현 기록에 남길 것.

현재는 커밋 ID·저장소 URL·브랜치·학생 PC 환경·실행 결과가 확인되지 않았습니다. 이 문서 자체도 실행이나 데이터 백업·복원 시험을 하지 않았습니다. 따라서 완료, 실행 성공, 외부 연결 성공, 복원 가능, 공식 단계 통과를 주장하지 않습니다.
