# 학생 실행 결과·동일 커밋 재현 기록

이 문서는 21단계 설명서에 따른 새 폴더 재현 절차와 13~21단계 결과를 **한 최종 커밋 기준으로** 기록하는 양식입니다. 빈칸은 아직 확인하지 않았다는 뜻입니다. 실제 실행·화면 확인·외부 연결 결과를 확인 없이 채우지 마세요.

> **현재 기록 상태: 미실행 / 커밋 정보 미기록.** 이 문서를 준비하는 동안 프로젝트 문서와 코드 설명만 읽었으며, Git clone, Node.js/PowerShell 실행, 브라우저 확인, 테스트 및 SDP/XDR·AI·OSV 연결을 수행하지 않았습니다. 따라서 아래에는 통과 결과나 실행 시각을 기재하지 않았습니다. 이번 문서 편집 후 새 Git 커밋을 만들거나 커밋 해시를 확인하지도 않았으므로, 편집 내용을 포함한 최종 기준 커밋도 아직 미기록입니다.

## 1. 재현 원칙

1. 원래 작업 폴더와 기존 기록은 보존합니다. 새 재현 폴더는 원본 저장소 바깥의 비어 있는 위치에 만듭니다.
2. 복제 전에 저장소 URL, 브랜치, **40자리 전체 커밋 해시**를 기록합니다. 브랜치는 위치 정보이고, 같은 소스인지 확인하는 기준은 전체 커밋 해시입니다.
3. 새 폴더의 `HEAD`가 기록한 해시와 정확히 일치하는지 확인한 뒤 실행합니다. 복제 과정이 끝난 후 다른 커밋으로 바꾸거나 파일을 수정했다면 그 결과는 별도 버전입니다.
4. 기존 폴더의 `.env`, 자격 증명, 인증서, 개인키, 토큰, 개인 설정 파일을 새 폴더로 무작정 복사하지 않습니다. 담당자가 별도로 안내한 연결 설정은 승인된 절차와 프로젝트 밖의 보관 위치를 따릅니다.
5. 모의 데이터, 기본 연결 없음, 실제 시스템 연결은 서로 다른 결과입니다. `demo` 화면이나 서버의 HTTP 응답을 SDP/XDR·AI 연결 성공으로 기록하지 않습니다.
6. 수정 후 새 커밋을 만들었다면 이전 해시에서 얻은 통과 결과를 새 해시의 결과와 합치지 않습니다. 최종 커밋에 대한 13~21단계 결과를 다시 확인해 한 묶음으로 기록합니다.

## 2. 실행 전 버전 기록

원본 작업 폴더를 보존한 상태에서 아래 정보를 먼저 적습니다. 저장소 주소에 사용자명·비밀번호·토큰이 포함되어 있으면 그 값을 기록하지 말고 제거하거나 안전한 별칭으로 바꿉니다. 개인 인증 정보는 이 문서, 캡처, 커밋에 넣지 않습니다.

| 항목 | 기록 |
|---|---|
| 저장소 URL 또는 안전한 별칭 | `미기록` |
| 소스 종류 | `미기록` (GitHub / 다른 Git 원격 / 로컬 Git 저장소 / 승인된 내보내기 패키지) |
| 원본에서 선택한 브랜치 | `미기록` |
| 재현 기준 최종 커밋 (정확히 40자리) | `미기록` |
| 원본 작업 트리 상태 | `미기록` (깨끗함 / 미커밋 변경 있음 — 변경이 있으면 먼저 필요한 내용을 커밋) |
| 원본 폴더 보존 확인 | `미기록` |
| 새 재현 폴더 별칭 | `미기록` (개인 경로 전체를 공개 기록에 적지 않아도 됨) |
| 재현 시작·종료 시각 및 시간대 | `미기록` |
| 기록 작성일 | `미기록` |

원본에서 URL·브랜치·해시를 확인하는 예시입니다. 명령은 안내용이며 이 문서 작성 시 실행하지 않았습니다.

```powershell
git -C "<원본 저장소 폴더>" remote get-url origin
git -C "<원본 저장소 폴더>" branch --show-current
git -C "<원본 저장소 폴더>" rev-parse HEAD
git -C "<원본 저장소 폴더>" status --short
```

`status --short`에 변경이 있으면 커밋되지 않은 파일은 커밋 해시에 포함되지 않습니다. 보존해야 하는 변경을 먼저 저장하고 커밋한 다음, 새 최종 해시를 기록합니다. 브랜치가 detached 상태라면 브랜치 칸에 그 사실과 기준으로 삼은 커밋을 적습니다. `rev-parse HEAD` 결과는 축약하지 않은 전체 해시를 기록합니다.

## 3. 새 빈 폴더에 같은 커밋 받기

재현 위치는 원본 저장소 폴더 안이 아닌 별도의 새 위치로 정합니다. 대상 폴더가 이미 파일을 포함한다면 사용하지 말고 다른 빈 위치를 선택합니다. 아래 `<...>`는 실제 값으로 바꾸는 자리표시자입니다.

### GitHub 또는 Git 원격 저장소

```powershell
$Repro = "<새 빈 폴더의 경로>"
git clone --branch "<기록한 브랜치>" --single-branch "<기록한 저장소 URL>" "$Repro"
git -C "$Repro" checkout --detach "<기록한 40자리 전체 커밋 해시>"
git -C "$Repro" rev-parse HEAD
git -C "$Repro" status --short
```

마지막 `rev-parse HEAD` 값이 2절의 전체 해시와 한 글자도 다르지 않은지 확인합니다. 해시가 다르거나 커밋을 찾을 수 없다면 실행을 시작하지 말고 원인을 기록합니다. `status --short`가 깨끗한지도 기록합니다.

### GitHub에 올리지 않은 로컬 Git 저장소

원본 폴더를 유지하고, 새 대상은 원본 바깥의 빈 위치로 지정합니다.

```powershell
$Repro = "<새 빈 폴더의 경로>"
git clone --no-hardlinks "<원본 로컬 Git 저장소 폴더>" "$Repro"
git -C "$Repro" checkout --detach "<기록한 40자리 전체 커밋 해시>"
git -C "$Repro" rev-parse HEAD
git -C "$Repro" status --short
```

로컬 저장소에서 해시를 가져올 수 없거나 일치 여부를 검증할 수 없으면 같은 커밋 재현으로 표시하지 않습니다. Git 저장소가 아닌 경우에는 담당자가 승인한 수료 패키지 내보내기 도구를 사용하고, 패키지의 기록이 기준 커밋을 식별하는지 확인합니다. 도구명·버전·내보낸 커밋·패키지 식별 근거를 남깁니다. 해시를 확인할 수 없는 패키지는 “동일 커밋 검증 불가”로 기록합니다.

### 복제본 확인란

| 확인 항목 | 결과 |
|---|---|
| 새 폴더가 원본과 분리되어 있고 처음에 비어 있었음 | `미확인` |
| 새 폴더 `HEAD`의 40자리 해시 | `미확인` |
| 원본 기준 해시와 일치 | `미확인` |
| 복제본 작업 트리 상태 | `미확인` |

| 원본 폴더를 변경·삭제하지 않았음 | `미확인` |
| 인증·설정 파일을 임의 복사하지 않았음 | `미확인` |

## 4. 런타임 확인·준비·설치·실행

실행 전에 3절의 해시가 일치해야 합니다. 이 프로젝트 문서와 `package.json`은 Node.js 24.19.0을 기준 버전으로 안내하며, 시작 PowerShell 스크립트는 Node.js 주 버전 22~24를 허용합니다. 이는 프로젝트의 버전 안내이지, 재현 PC의 설치 상태를 확인했다는 뜻은 아닙니다.

1. 새 복제본에서 앱 폴더, 즉 `package.json`, `tools`, `src`가 함께 있는 폴더를 찾습니다. 이 프로젝트의 학생 배포 구조에서는 보통 프로젝트 폴더 안의 `on-client`입니다. 원본 폴더가 아니라 새 복제본의 앱 폴더를 사용합니다.
2. 해당 앱 폴더에서 PowerShell을 열고 버전을 기록합니다.

```powershell
node --version
npm --version
$PSVersionTable.PSVersion
```

3. Node.js가 없거나 수업 기준과 다르면 공식 또는 기관이 승인한 배포 경로와 강사 지침으로 런타임을 준비합니다. 설치 후 PowerShell 창을 새로 열어 위 버전 확인을 다시 수행하고 기록합니다. 실제 설치·업데이트 결과는 학생이 확인하기 전까지 미확인입니다.
4. 이 커밋의 `package.json`에 외부 npm 의존성이 선언되어 있지 않은 제공 구성에서는 `npm install`이 필요하지 않습니다. 다른 학생 프로젝트의 실제 매니페스트가 의존성이나 잠금 파일을 포함한다면 그 커밋의 문서 지침을 따르고 실행한 명령을 기록합니다. 임의로 설치 단계를 추가하지 않습니다.
5. 앱 폴더의 PowerShell에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

6. 출력된 로컬 주소와 서버 시작 메시지를 기록합니다. 기본 주소는 `http://127.0.0.1:5189/`입니다. 서버 응답 메시지는 로컬 앱 서버 응답만 뜻하며 AI나 실제 시스템 연결 성공을 의미하지 않습니다.
7. 브라우저에서 출력된 주소를 열고, 표시된 메뉴·상태·오류를 확인합니다. 사용한 브라우저 종류와 버전, 확인 시각, 민감정보를 가린 증거 ID를 기록합니다.
8. 실행한 PowerShell 창에서 `Ctrl+C`를 눌러 종료하고 종료 시각을 기록합니다. 같은 복제본·같은 커밋에서 실행 절차와 브라우저 확인을 다시 수행하고 재실행 결과를 기록합니다. 포트를 바꿨다면 두 실행 모두 사용한 포트와 브라우저 주소를 남깁니다.

**중요:** 기존 프로젝트의 `.env`, AI 자격, SDP 설정, 인증서·키·토큰을 복사하거나 문서·화면 캡처에 넣지 않습니다. 담당자가 별도 설정을 안내한 경우에만 안전한 별도 위치의 설정을 사용하고, 이 기록에는 설정의 내용 대신 “담당자 제공 설정 사용 여부”만 남깁니다.

### 단계별 화면·자료 확인 위치와 기대 관찰

아래 기대 관찰은 안내서와 코드 계약을 바탕으로 한 **확인 기준**입니다. 실제 화면에서 확인하기 전에는 결과 칸을 `확인됨`으로 바꾸지 않습니다. 오류·연결 없음·예제 상태도 실제로 본 그대로 기록합니다.

| 단계 | 학생이 볼 화면·자료 | 기대 관찰 기준 (실행 전 예상이며 통과 판정 아님) |
|---:|---|---|

## 6. 근거 목록과 증거 보호

| 근거 ID | 단계 | 형식·설명 | 생성 시각·시간대 | 저장 위치 또는 참조 | 민감정보 제거 확인 |
|---|---:|---|---|---|---|
| 미확인 | — | 아직 근거 없음 | 미확인 | 미확인 | 해당 없음 |

근거는 화면 캡처, 안전한 오류 코드, 터미널의 비밀정보 없는 시작·종료 신호 등 실제로 확인한 자료만 등록합니다. 캡처 전 계정명, 이메일, 개인 데이터, 호스트 설정 경로와 자격 등 공유가 불필요한 정보를 가립니다. 자격 파일·설정 원문, 토큰, 키, 비밀번호를 증거로 첨부하지 않습니다. 증거가 없으면 통과로 간주하지 않습니다.

## 7. 수정·최종 커밋 기록

문제를 고쳐 새 커밋을 만들었다면 새 행을 추가하고, 새 해시에서 실행한 결과를 별도 기록합니다. 아래 표의 서로 다른 해시 행에 있는 확인 결과를 합산해 한 최종 버전의 전체 성공으로 표현하지 않습니다. 이 기록 문서의 수정도 제출 코드에 포함하려면 먼저 커밋한 뒤 그 40자리 해시를 새 기준으로 삼고, 새 복제본에서 재현 절차를 다시 진행합니다. 이 편집에 대한 커밋 생성·해시 확인은 아직 하지 않았습니다.

| 버전 구분 | 저장소·브랜치 | 전체 커밋 해시(40자리) | 변경 요약 | 13~21단계 재실행 범위·결과 기록 위치 | 최종 기준 여부 |
|---|---|---|---|---|---|
| 최초 재현 기준 | 미기록 | 미기록 | 해당 없음 | 미확인 | 미정 |
| 이 기록 수정 반영 버전 | 미기록 | 미기록 | 재현 기록의 단계별 화면 확인 기준 보강 | 미확인 — 해당 커밋에서 다시 실행 필요 | 미정 |

최종 보고 전에 최종 기준 행의 커밋 해시와 새 복제본의 `git rev-parse HEAD`가 일치하는지 다시 확인합니다. 한 기능이라도 최종 해시에서 미확인이라면 전체 결과를 “모두 재현됨”으로 표시하지 않습니다. 로컬 기능 시험, 모의 데이터 결과, 실제 연결 성공, 공식 ALEPH 단계 판정은 각각 별개로 보고합니다.
