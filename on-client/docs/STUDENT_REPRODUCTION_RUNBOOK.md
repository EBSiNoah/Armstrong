# 학생 실행·재현 안내서

이 문서는 프로젝트를 받은 사람이 실제 앱 폴더와 실행 순서를 찾고, 로컬 화면과 외부 연결의 경계를 구분하도록 돕습니다. 기존 문서나 `docs/STUDENT_RUNBOOK.md`는 수정하지 않았습니다.

**확인 범위:** 이번 문서 작성에서는 파일과 코드에 적힌 계약·명령을 읽었습니다. PowerShell 명령, Node.js 서버, 브라우저, 테스트, SDP/XDR, AI 게이트웨이는 실행하거나 접속하지 않았습니다. 따라서 아래의 화면과 실행 신호는 코드상 예상이며, 이번 작업에서 실제로 확인한 실행 결과가 아닙니다.

## 1. 필요한 프로그램과 버전 확인 범위

| 프로그램 | 프로젝트에서 확인한 요구·설정 | 이번에 실제 설치 버전을 확인했나? |
|---|---|---|
| Node.js | `package.json`의 `engines.node`는 `24.19.0`입니다. `tools/start-alekov.ps1`은 Node.js 주 버전 22~24를 허용하고 `24.19.0`을 권장합니다. | 아니요. 이 컴퓨터의 설치 버전은 확인하지 않았습니다. |
| PowerShell | 실행 도구가 Windows PowerShell 스크립트(`.ps1`)입니다. | 아니요. PowerShell 버전은 확인하지 않았습니다. |
| npm | `package.json`에 `start`, `demo`, `check` 스크립트가 정의돼 있습니다. | 아니요. npm 버전은 확인하지 않았습니다. |
| 웹 브라우저 | 로컬 웹 화면을 표시할 브라우저가 필요합니다. | 아니요. 브라우저 종류·버전·호환성을 확인하지 않았습니다. |

`package.json`에 `dependencies` 항목은 없습니다. 프로젝트 문서는 외부 npm 의존성이 없다고 안내합니다. 아래의 실행 명령에는 코드와 문서에서 찾지 못한 설치 명령을 덧붙이지 않았습니다.

## 2. 폴더 구조와 PowerShell을 여는 위치

현재 저장소에서 앱 폴더의 경로는 `Armstrong-main/on-client/`입니다. 배포본에서는 프로젝트 안의 `on-client` 폴더가 앱 폴더입니다. 아래 명령은 `package.json`, `tools`, `src`가 함께 있는 **앱 폴더에서** 실행합니다.

```text
Armstrong-main/on-client/
├── package.json                 # Node 요구 버전과 start/demo/check 스크립트
├── README.md
├── docs/                        # 실행·단계·연결 안내
├── public/
│   ├── index.html               # 브라우저 문서
│   ├── app.js                   # 제공 UI, API 요청, 학생 모듈 연결
│   └── style.css
├── src/
│   ├── server.mjs               # 앱 서버와 API
│   ├── engine.mjs               # 연결 없음·demo·엔진 선택
│   ├── engine/                  # SDP 호스트 경계
│   └── ai/                      # 서버 측 AI·앱 연결 코드
├── student/
│   ├── extension.mjs            # 학생 표시 함수
│   └── engine-adapter.mjs       # 서버가 제공한 엔진 기능의 어댑터 경계
├── tools/
│   └── start-alekov.ps1         # 실행 전 점검 및 서버 시작
└── vendor/                      # 저장소에 포함된 서버 측 HTTP 클라이언트
```

**PowerShell 여는 위치:** 파일 탐색기에서 실제 `on-client` 앱 폴더를 연 다음 주소 표시줄에 `powershell`을 입력하고 Enter를 누릅니다. 새 창의 현재 폴더가 `on-client`인지 확인합니다. 저장소 상위 폴더나 `docs` 폴더가 아니라 앱 폴더에서 실행합니다. 시작 스크립트는 앱 폴더와 링크/바로가기 여부를 점검합니다.

## 3. 실행·브라우저 확인·종료·재실행

### 기본 실행

앱 폴더의 PowerShell에서 다음 명령을 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

실행 도구는 앱 폴더·Node 버전·포트 사용 여부를 점검한 뒤 `src/server.mjs`를 시작하고, 기본 포트에서 HTTP 200 응답을 기다리도록 작성되어 있습니다. `-ExecutionPolicy Bypass`는 이 명령에서 시작하는 PowerShell 실행에만 적용됩니다.

### 브라우저 주소와 시작 신호

- 기본 포트: `http://127.0.0.1:5189/`
- 실행 도구의 대체 포트 예: 명령에 `-Port 5190`을 지정한 경우 `http://127.0.0.1:5190/`

스크립트가 서버 응답을 확인하면 다음 문구를 출력하도록 작성돼 있습니다(주소와 포트는 실행값에 따라 달라집니다).

```text
케셰브가 켜졌습니다. 브라우저에서 http://127.0.0.1:5189/ 을 여세요.
서버가 응답한 것만 확인했습니다. AI 연결 상태는 화면에서 따로 확인해 주세요.
끄려면 이 창에서 Ctrl+C 를 누르세요.
```

이 신호는 **로컬 앱 서버가 HTTP 응답을 했다는 뜻만**입니다. SDP/XDR 접근 제어, AI 포털 승인, AI 모델 응답 성공을 뜻하지 않습니다. 이번에는 이 신호가 실제로 출력되는지 실행해 확인하지 않았습니다.

브라우저에서 기본 주소를 열었을 때 코드·기본 설정에 따른 예상은 다음과 같습니다.

- 케셰브 화면과 `보호 현황`, `업무 앱`, `보안 기록` 메뉴가 표시됩니다.
- 기본 엔진은 외부 엔진 연결이 없도록 정의되어 있습니다. 각 API 응답에 따라 상단 상태는 연결 없음 또는 확인 불가가 될 수 있으며, 이를 실제 연결 성공으로 해석하지 않습니다.
- AI 연결 점검 전에는 “AI 연결 점검 전입니다” 상태가 표시됩니다. 설정값 또는 앱 서버 시작만으로 AI 사용 권한이 확인된 것은 아닙니다.
- 아래 학생 구현 영역은 `student/extension.mjs`에서 생성하는 별도 영역입니다. 기본 제공 UI의 표시와 학생 단계 통과는 같은 의미가 아닙니다.

이 내용은 코드에 근거한 **예상 화면**이며, 실제 화면을 이번 작업에서 확인한 결과가 아닙니다.

### 프로젝트에 정의된 다른 실행 명령

`on-client` 폴더에서 `package.json`이 정의한 명령만 사용합니다.

| 명령 | 확인 범위·주의 |
|---|---|
| `npm start` | `node src/server.mjs`를 실행합니다. 실행 도구의 사전 폴더·Node 버전·포트 확인을 거치지 않습니다. |
| `npm run demo` | `node src/server.mjs --demo`를 실행합니다. 예제 데이터이며 실제 시스템 연결이 아닙니다. |
| `npm run check` | `node --check student/extension.mjs`로 학생 모듈의 문법을 확인하는 스크립트입니다. 화면·기능·네트워크·과제 통과 검사는 아닙니다. |

처음 실행할 때는 폴더·버전·포트와 서버 응답을 점검하는 PowerShell 실행 도구를 우선 사용합니다. 실제 실행 여부는 학생이 로컬에서 확인해야 합니다.

### 종료와 다시 실행

1. 기본 방식으로 실행했다면 실행한 PowerShell 창에서 `Ctrl+C`를 누릅니다.
2. 서버 프로세스가 끝난 것을 확인합니다.
3. 다시 켤 때는 같은 `on-client` 앱 폴더에서 기본 실행 명령을 다시 실행합니다.
4. PowerShell에 나온 주소를 브라우저에서 엽니다. 대체 포트를 썼다면 브라우저 주소에도 같은 포트를 씁니다.

`-Background`는 백그라운드 실행 옵션입니다. 사용 시 실행 도구가 알려 주는 `node` 프로세스 번호를 확인해 작업 관리자에서 종료합니다. 이 옵션과 종료 절차는 코드상 안내이며, 여기서 실행해 검증하지 않았습니다.

## 4. 글로 쓴 구성도와 공개 주소

아래는 파일에서 확인한 코드 경계의 개요입니다. 화살표는 구현·설정 경로를 나타낼 뿐, 실제 네트워크 연결이 성공했다는 보고가 아닙니다.

```text
[브라우저]
    │ 같은 PC의 HTTP 요청
    │ http://127.0.0.1:5189/
    ▼
[로컬 Node.js 앱 서버: src/server.mjs]
    ├── 화면: public/index.html, public/app.js, public/style.css
    ├── 접근 판정·사용자/기기/세션·기록 API
    │       └── 기본 실행: 연결 없음
    │           demo 실행: 예제 엔진(실제 연결 아님)
    │           담당자가 설정한 경우:
    │             src/engine/* + student/engine-adapter.mjs
    │               → 서버가 제공하는 호스트 기능
    │                 → 접근 제어·SDP / XDR 시스템
    └── AI 점검·사건 설명 API
            → src/ai/service.mjs (서버 측 권한·응답 검사)
              → 서버 측 AI 게이트 클라이언트
                → 설정된 AI 게이트웨이

브라우저는 SDP/XDR 시스템이나 AI 게이트웨이에 직접 연결하지 않습니다.
AI 비밀 자격·SDP 자격은 브라우저 주소나 학생 표시 코드에 넣지 않습니다.
```

공개 가능한 주소와 미확인 범위:

- 앱 주소는 기본 `http://127.0.0.1:5189/`이며, 로컬 PC에서 쓰는 주소입니다.
- `src/ai/connection.mjs`에는 앱 연결 절차용 게이트 origin `https://ai-classroom-gateway-production.up.railway.app`와 승인 포털 origin `https://aleph-omega.vercel.app`이 코드 상수로 있습니다. 포털 주소는 승인 흐름용이며 모델 게이트웨이와 같은 주소라고 단정하지 않습니다. 두 주소 모두 이번 작업에서 접속 또는 서비스 상태를 확인하지 않았습니다.
- 모델 요청의 서버 주소는 `src/ai/service.mjs`에서 `ON_AI_BASE_URL` 설정으로 받습니다. 실제 배포 설정과 비밀값은 문서에 기록하지 않습니다.
- 실제 SDP/XDR 호스트는 담당자가 별도로 전달하는 설정에 따라 정해집니다. 실제 호스트 주소, 자격 파일 경로, 인증서·키·토큰 내용은 쓰지 않습니다.

아래 “코드에서 확인”은 구현 위치와 정적 흐름을 파일에서 읽었다는 뜻입니다. 앱을 실행하거나 기능을 동작시켜 확인했다는 뜻은 아닙니다.

| 기능 | 함수·파일 경계 | 코드에서 확인한 범위 | 이번 작업에서 실제 기능 확인 |
|---|---|---|---|
| 학생 화면 | `student/extension.mjs`: `createStudentView()`, `renderIdentity`, `renderDecision`, `renderEvents`, `renderStatus`, `renderAiConnection`, `renderExplanation`, `renderAction`, `renderVulnerabilities` | 학생 구현 표시 함수가 있고, 제공 UI가 `public/app.js`에서 해당 표시 슬롯을 호출합니다. | 아니요. 브라우저 렌더링과 사용자 상호작용은 미실행입니다. |
| 제공 브라우저 UI·요청 | `public/app.js` | 서버 요청·응답 검사, 상태 관리, 제공 UI와 학생 모듈 연결 코드가 있습니다. | 아니요. API 호출·화면 상태는 미실행입니다. |
| 로컬 서버 | `src/server.mjs` | 앱 서버/API 구현 위치이며 PowerShell/npm 명령이 이 모듈을 실행하도록 되어 있습니다. | 아니요. 서버 기동과 API 응답은 미확인입니다. |

| 취약점 조회 | `src/vulnerabilities/` | 패키지 조회 구현 위치를 확인했습니다. | 아니요. OSV 조회 결과·취약점 상태는 미확인입니다. |
| 실행 도구 | `tools/start-alekov.ps1` | 실행 전 검사, 로컬 서버 시작, HTTP 응답 대기 및 출력 문자열이 있습니다. | 아니요. PowerShell과 브라우저에서 실행하지 않았습니다. |

### 학생 모듈 호출 계약에서 확인한 주의점

`public/app.js`는 `createStudentView({ api, onChange })`처럼 인자 객체를 전달합니다. 현재 `student/extension.mjs`의 함수 선언은 `createStudentView()`이며 매개변수를 받거나 `api`/`onChange`를 사용하지 않습니다. JavaScript에서 여분의 인자를 넘기는 것 자체는 오류가 아니지만, 학생 코드가 그 API를 사용한다고 안내하거나 실제 연동된 것으로 간주하면 안 됩니다. 단계별 변경 전 `docs/IMPLEMENTATION_CONTRACT.md` 및 프롬프트와 실제 함수 계약을 대조하세요. 제공 파일을 임의로 고치지 않습니다.

| 증상 | 확인 순서 | 구분·다음 조치 |
|---|---|---|

| 포트 5189를 사용할 수 없음 | 다른 프로그램을 종료하지 말고 실행 명령에 `-Port 5190` 지정 → `http://127.0.0.1:5190/` 열기 | 코드에 있는 대체 포트 사용 순서입니다. |
| 앱 폴더/시작 틀 폴더 오류 | `package.json`, `src`, `tools`가 있는 실제 `on-client`인지 확인 → 파일 탐색기에서 그 폴더를 열어 PowerShell 다시 시작 | 상위 폴더, `docs`, 바로가기 경로에서 실행하지 않습니다. |
| 서버가 지정 시간 안에 응답하지 않음 | PowerShell 창의 오류 전체 확인 → 실행 폴더와 포트 확인 → 담당자에게 메시지 전달 | 서버 응답 확인 실패를 연결 성공으로 기록하지 않습니다. |
| 브라우저에서 페이지가 열리지 않음 | 서버 실행 창이 살아 있는지 확인 → 출력된 URL·포트가 일치하는지 확인 → 같은 폴더에서 재실행 | 해결되지 않으면 오류 전문과 주소를 담당자에게 보여 줍니다. |
| 화면에 `연결 없음`, `demo`, `확인 불가`가 표시됨 | 기본 실행인지 demo인지 구분 → 담당자가 연결 설정을 발급했는지 확인 → 안전한 오류 코드 확인 | demo는 예제입니다. 미연결·확인 불가를 연결 성공으로 바꾸거나 빈 성공으로 처리하지 않습니다. |
| AI 점검/사건 설명 실패 | 로컬 서버 응답과 AI 권한·모델 응답을 구분 → 화면의 오류 코드와 안전한 도움정보 확인 → 담당자에게 앱 권한·게이트 상태 문의 | 키·토큰·설정 원문을 복사하거나 임의로 입력하지 않습니다. `docs/CONNECTION_TROUBLESHOOT.md`를 참고합니다. |
| 기록·기기·세션 조회 실패 | 오류 코드 확인 → `CONTRACT_MISMATCH`나 `ENGINE_RESULT_UNVERIFIED`면 확인 불가로 취급 → 담당자에게 연결 어댑터·응답 계약 확인 요청 | 실패를 정상 빈 목록으로 간주하지 않습니다. |

재시도는 화면의 제공 동작을 사용자가 직접 실행합니다. 추측한 명령이나 자동 재시도 동작을 이 안내서에 덧붙이지 않았습니다.

## 9. 상태 문구·계약 보존 기준

아래 한국어 표기는 학생 화면 상태 문구를 작성할 때의 기준입니다. API가 전달하는 상태값은 기계 계약이므로 번역·개명·치환하지 않습니다. 화면에는 필요한 경우 한국어 설명과 원래 값을 함께 표시합니다. 함수명, 입력 필드, `data-*` 속성 이름·값 형식, 필수 접근 가능한 이름도 바꾸지 않습니다. 이 절은 문구 기준이며 코드 계약을 변경하지 않습니다.

### 공통 요청 상태와 연결 모드

| 원래 값 | 화면 문구 기준 | 구분 |
|---|---|---|
| `idle` | 아직 요청하지 않았습니다 | 요청 전 상태입니다. 처리 완료를 뜻하지 않습니다. |
| `loading` | 조회 중 / 요청 처리 중 | 실제 작업에 맞는 동사를 씁니다. 조회와 집행을 한 표현으로 뭉뚱그리지 않습니다. |
| `ok` | 조회 완료 / 응답 확인 | 해당 API 응답을 받았다는 뜻입니다. 외부 조치의 효과나 실제 서비스 연결 성공으로 확대 해석하지 않습니다. |
| `error` | 요청 실패 / 조회 실패 | 실패한 작업을 명시합니다. 접근 거부 판정, 빈 결과, 조치 효과 없음으로 바꾸지 않습니다. |
| `connected` | 연결됨 (`connected`) | 연결 상태입니다. 별도의 기능 결과가 확인됐다는 뜻은 아닙니다. |
| `demo` | 예제 데이터 (`demo`) · 실제 시스템 연결 아님 | 모의 데이터와 실제 연결을 명확히 구분합니다. |
| `disconnected` | 연결 없음 (`disconnected`) | 외부 연결이 없는 상태입니다. |
| `unknown` | 확인 불가 (`unknown`) | 결과를 검증할 수 없는 상태입니다. 정상·안전·허용으로 바꾸지 않습니다. |

### 접근 판정·보안 이벤트 상태

| 원래 값 | 화면 문구 기준 | 유의 사항 |
|---|---|---|
| `allow` | 접근 허용 (`allow`) | 서버 판정의 허용입니다. 실제 대상 앱 접속 성공을 뜻하지 않습니다. |
| `deny` | 접근 거부 (`deny`) | 정책 판정입니다. 요청 자체의 오류와 구분합니다. |
| `challenge` | 추가 확인 필요 (`challenge`) | 추가 인증 또는 확인 절차가 필요합니다. 화면이 그 절차를 대신 수행했다고 쓰지 않습니다. |
| `unknown` | 판정 확인 불가 (`unknown`) | 허용·거부 어느 쪽으로도 간주하지 않습니다. |
| `access` | 접속 기록 (`access`) | 이벤트 종류의 원래 값 `access`를 보존합니다. |
| `xdr` | XDR 경보 (`xdr`) | 이미 기록된 경보를 표시하는 것이며, 화면 진입 시 새로 탐지했다는 뜻이 아닙니다. |
| `allowed` / `denied` | 허용됨 (`allowed`) / 거부됨 (`denied`) | 이벤트 상태 필드의 원래 값과 판정 응답의 `allow` / `deny`를 서로 치환하지 않습니다. |
| `active` / `expired` / `revoked` | 활성 (`active`) / 만료 (`expired`) / 회수됨 (`revoked`) | 세션 상태를 구분하고 원래 값을 유지합니다. |
| `compliant` / `noncompliant` | 보안 기준 준수 (`compliant`) / 보안 기준 미준수 (`noncompliant`) | 기기 준수 상태를 표시합니다. |

### AI 조치 처리 상태

| 원래 값 | 화면 문구 기준 | 상태 해석 |
|---|---|---|
| `idle` | 아직 미실행 (`idle`) | 제안·요청·효과가 확인되지 않은 초기 상태입니다. |
| `loading` | 조치 준비 중 또는 원천 결과 조회 중 (`loading`) | 실제 진행 중인 작업을 구체적으로 씁니다. |
| `prepared` | 준비됨 · 미실행 (`prepared`) | 사람 확인 전이며 집행되지 않았습니다. 확인 기한이 있으면 그대로 표시합니다. |
| `executing` | 서버로 요청 전달 중 (`executing`) | 처리 결과가 아직 확인되지 않았습니다. 완료나 성공이라고 쓰지 않습니다. |

| `denied` | 요청 거절 (`denied`) | 거절 응답만으로 실제 효과가 없었다고 단정하지 않습니다. |
| `failed` | 처리 실패 (`failed`) | 실패 상태만으로 실제 효과가 없었다고 단정하지 않습니다. |
| `unknown` | 결과 확인 불가 (`unknown`) | 성공이나 효과 없음으로 판단하지 않습니다. 원천 결과 재조회와 조치 재전송을 구분합니다. |
| `error` | 요청 오류 (`error`) | 오류를 판정 결과나 집행 결과로 바꾸지 않습니다. |
| `expired` | 확인 기한 만료 (`expired`) | 현재 준비 상태로 집행할 수 없음을 표시합니다. |

### 고정 계약 항목

다음 이름은 문장 다듬기 대상이 아닙니다. 그대로 유지하고, 표시 문구와 분리해서 취급합니다.

- 학생 표시 함수명: `renderIdentity`, `renderDecision`, `renderEvents`, `renderStatus`, `renderAiConnection`, `renderExplanation`, `renderAction`, `renderVulnerabilities`.
- 프롬프트에 지정된 필수 선택 상자 접근 가능 이름: `기록 종류`, `업무 앱`, `접속 상태`.
- 필수 버튼 접근 가능 이름: `도움정보 복사`, `<event.id> 상세`, `<action> 미지원`. `<event.id>`와 `<action>`은 실제 입력값으로 치환하되 이름 규칙은 유지합니다.
- 프롬프트에 지정된 표식: `data-student-event-id`, `data-student-event-detail`, `data-student-explanation-event`, `data-student-action-event`, `data-student-action-request`, `data-student-package-name`, `data-student-package-version`. 속성명은 번역하거나 새 이름으로 바꾸지 않습니다.
- 상태 코드·필드명·속성 외에 임의의 상태값을 만들지 않습니다. 오류 메시지는 허용된 계약에 따라 표시하되, `error`를 `deny`, `unknown`, 빈 목록 또는 성공으로 변환하지 않습니다.

이 문구 기준은 정적 계약 설명입니다. 실제 화면 문구의 반영 여부와 브라우저 렌더링은 확인하지 않았습니다. 실제 확인 전에는 통과·실행 완료로 기록하지 않습니다.
